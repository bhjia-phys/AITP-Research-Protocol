# Start or organize a research topic

Use this at first entry into a new topic, when existing material lacks a coherent
main note, or when the researcher requests a substantial consolidation. First
check for an established main note, including one named differently or written
in TeX. Ordinary resumption uses that note and the links needed for the task.

## Establish what the note should answer

Start with the user's request and earlier decisions. Inspect the existing README,
the complete main note if present, and enough relevant source material to orient
the discussion. Identify the physical or mathematical setting, intended question,
learning or research purpose, and whether several independent questions are being
mixed together. Infer language, audience and paths from explicit preferences and
usable local conventions. Use
[aitp-human-brainstorming](../../aitp-human-brainstorming/SKILL.md) when a
consequential choice remains unresolved; do not repeat its interaction as a
separate intake phase here.

State your understanding briefly in conversation, with the specific uncertainty
and why it matters. Ask early, before committing that uncertainty to the main
argument. For example: "Is this an isolated layer or a periodic bulk material?
The boundary conditions change the screening problem and the claim the note can
make." Prefer a small, answerable question to a general request
for the researcher to describe everything. Do not delay an already apparent
question until after an exhaustive archive scan or a polished draft.

Wait for the answer before dependent writing or relocation. Continue independent
source reading and identifying useful assets when authorized. Missing evidence
is different from missing intent: investigate evidence with the available tools;
ask the researcher about intended scope or genuinely unavailable inputs. An open
proof or unknown result belongs in an agreed research note, not in a demand that
the user solve it first. If exploration itself is the agreed task, retain candidate
questions and provisional assumptions explicitly. When choices are already clear,
start without another confirmation round.

## A new topic

Use the designated working folder; if none is established, suggest a home near
related work and resolve ambiguity before saving there. The
[optional asset layouts](local-assets.md#optional-layouts-for-a-new-home) provide
a starting point. Create `research.md` and explain the new folder in the nearest
suitable README; add a local README when its own material locations need explanation.
Add other files as material develops, not as empty scaffolds.

Write the smallest coherent account supported so far: what is being asked and
why, the setting and relevant known background, a proposed route and its assumptions,
and the first derivation or observation that could clarify the question. Label
untested ideas as proposed. A new topic need not have results or a fixed hypothesis.
Use the [main-note templates](../../aitp-writing/references/research-note.md) as
starting points: an honest abstract, introduction and proposed route can be enough
at this stage. Omit unused sections. Use the requested language and level of explanation.

A learning topic follows the same rule of one main note. That note can be told as a
[story of questions](shared-knowledge.md#tell-a-learning-topic-as-a-story-of-questions),
either as the topic's `research.md` or as a story in the researcher's shared collection,
but not both.

Let the scientific dependencies shape the note. In formal work, make the objects,
conventions and missing argument explicit. In computational work, connect the
approximation and observable to a discriminating calculation and its checks.
In mixed work, explain precisely which analytic statement the numerical test
would support or challenge. Use [aitp-writing](../../aitp-writing/SKILL.md) for
the relevant exposition; these distinctions do not require three directory schemes.

## An existing topic

Determine whether the request is to resume a question, synthesize scattered work,
or migrate its home. Organizing a note does not imply moving assets or archiving
the original project. Read an existing main argument in full before revising it.
When there is no main note, discover questions from manuscripts, detailed notes,
code and result reports. For broad recovery, cover each discovered branch and
its corrections and useful failures; for a scoped request, stay within that scope.

Use primary evidence to resolve stale summaries where possible. Distinguish an
outdated draft from a later correction, and a tested small case from an unproved
general claim. If conflicting versions cannot be reconciled, expose the conflict
and ask about missing context before adopting one as the main account. Identify
unexamined or unavailable material; do not call a selective synthesis complete.

Independent questions normally get separate folders and main notes, even when
they share code. An agreed independent branch follows the same rule; reuse an
established folder and main note if they already cover it. Supporting routes to
the same question can remain linked sections or detailed notes;
[a side investigation](../../aitp-writing/references/supporting-notes.md#follow-a-side-investigation)
can also reuse another established topic while retaining its originating question.
Within authorized organization, implement a separation clearly supported by the
existing questions without another confirmation. If competing groupings change
the scientific scope or priority, resolve that choice before consolidating.
Preserve established filenames, PDF and TeX sources, scripts,
data and figures. Explain their useful locations in the README and connect the
argument to precise sources. Follow the asset guide's recovery checks only when
full migration or archive readiness is requested.

## Develop the note together

For a substantial consolidation whose direction needs discussion, show a short
proposed line of argument in the conversation, not a separate planning document.
Resolve the consequential questions, then write within that understanding. Do not
require approval of every paragraph. If new evidence changes the agreed question
or reveals an essential objection, bring that to the researcher when it appears.
Investigate scientific objections rather than treating agreement as verification.

After a meaningful draft or revision, show the note and explain the supported
answer and remaining gap. Invite correction of the scope or reasoning without
making routine continuation wait for approval. Integrate substantive corrections
where they change the argument; ordinary discussion with no durable change needs
no memory write. A demonstrated reusable procedure can later be taught through
[aitp-distill](../../aitp-distill/SKILL.md), using its linked evidence as well as
the main note. The research note remains the developing account of the topic.
