# Find and retain a domain method

Use the topic's main note and relevant links to identify a method already used
there. For a general method supplied by AITP, look under
`aitp-research/methods/<domain>/<method>/SKILL.md`. The first supplied method is
[developing LibRPA](../methods/librpa/developing-librpa/SKILL.md). Read a method's
instructions only when its task matches the present work; do not load the library
at topic entry. Domain folders are ordinary organization, not separate protocols.

Keep general, shareable procedures in this library when editing AITP is within
the task's scope. Keep unpublished evidence, account settings and local paths in
the topic or its established shared family location. An unreviewed method can
remain in `topic/skills/<method>/SKILL.md` until its reusable part is ready for
inclusion. Existing local Skills remain useful; no migration is required.

Use [aitp-distill](../../aitp-distill/SKILL.md) to extract or revise a procedure
from the main note and its evidence. Add an ordinary relevant link for discovery;
there is no registry or knowledge-card layer. Links from `aitp-research` provide
portable discovery. Host catalogs can differ: Codex can also expose a nested
`SKILL.md` directly, while Hakimi loads the containing research Skill as one
bundle. There are four core roles, but not necessarily only four selectable
Skills in every host. A directly selected method still starts with memory for
research-topic work. Do not edit an installed plugin cache as its durable home.

Generalizing a procedure does not authorize publishing its motivating research
note, data or examples. Preserve any review boundary already specified by the
researcher. Prepare those materials outside the outgoing public tree until their
publication is authorized; a generic method should be usable without them.
