M1c (done; deterministic gate passed) adds a **repeatable** `--workstream <slug>` flag to `record prepare`/`note prepare` (duplicates rejected, no dedup) and a **single-occurrence** `--workstream <slug>` flag to `enter`/`list` (repeated flags are parser-rejected); scoped `--json` payloads use `aitp/enter-0.3`/`aitp/list-0.2` with one additive top-level singular `workstream` key and strictly scoped projections (never an out-of-scope handoff); without the flag `aitp/enter-0.2`/`aitp/list-0.1` stay byte-unchanged. - The binding simplicity ratchet is normative in `docs/roadmap.md` §Simplicity and stage authorization: gate isolation, caps-as-ceilings, natural-use pause, and episodic evaluation are defined there.
- The exhaustive A–H roster, dispositions, and reviewed-change/no-spec rules are normative in `docs/m1b-spec.md` §0.1; use that section rather than duplicating policy here.
- M2/M3 remain design options; schedule them only under their own natural-demand evidence in the roadmap.
- Whenever a change alters stage status, roadmap scope, CLI surface, gate evidence, spec paths, runtime budgets, installation, or user-facing operation, update the corresponding `README.md` roadmap/current-state sections in the same change; never defer README maintenance to a later session. Completed specs, adjudications, and stage notes live frozen in `docs/archive/` and take no part in any sync discipline.
- `feedback/README.md` is the current natural-use feedback triage surface. Keep dated feedback records at their original paths and preserve their observed content; archive them logically in that index only after reviewed adjudication or an absorbed completed change. New dated records continue to land in `feedback/` from `feedback/natural-use-session-template.md` and are active until triaged. Logical archive status never promotes a deferred capability or replaces the canonical roadmap/disposition.
- The Hakimi integration handoff lives in `docs/hakimi/` (`README.md`, `compatibility-matrix.md`); update it in the same change as any stage status, CLI surface, or schema change, per its own maintenance contract.
- Keep the machine-readable adapter surface `plugins/aitp-research-protocol/aitp.contract.json` (`aitp/adapter-contract-0.1`) in the same change as every CLI command/flag, transport schema, model-facing tool description, or Skill-surface change. `tests/ledger/test_adapter_contract.py` pins it to plugin versions, CLI help, live JSON schema names, and Skill paths. Hakimi and external adapters (including dsh) consume this contract and must fail closed on an unknown contract schema.
- Keep one canonical runtime implementation: `plugins/aitp-research-protocol/scripts/vendor/aitp/`; do not hand-maintain a copied plugin runtime.
- Keep each Python module below 400 nonblank lines, and keep the total canonical runtime within the cumulative budget in `docs/roadmap.md` (~2,000 lines maximum; M0.6 ends ≤ 1,100).
- Keep the installable Codex bundle under `plugins/aitp-research-protocol/`.
- Preserve the core command groups and contracts: `init`, `enter`, `record`, and `note`. Later commands (`show`, `list`, `check`, `compile`, `catalog`, `link`) are additive and must not weaken the core contracts.
- Cross-topic and compiled-artifact features must consume ledger records through the public parser and must never rewrite source records.
- Cross-Topic links require explicit human-confirmed save; inferred links remain drafts.
- Default to no index: `rg` over Markdown is the query path. Permit a derived cache only after a benchmark demonstrates the need; it must be disposable and rebuildable.
- Agents maintain current state automatically at session boundaries — never the researcher's job, per `using-aitp`: at session start run `enter`/`check` (fail closed on exit 2), review the evidence behind every claim you will rely on, and retrieve method cards by their generic marker (`rg "^> method-card:"` over `.aitp/topic/` — no index, no enumeration); at session end, only when the session produced a durable delta and the recorded current state is behind it, append the missing closeout and/or working Note yourself with `authority: agent` (superseding only the stale agent-authority closeout/working Note — never a human `decision`/`result` — and never editing it; no durable delta ⇒ zero-write) and verify with `check`/`enter` after every save. Skill judgment, never a runtime rule; no behavior-superiority claim.
- Method-card distillation follows `plugins/aitp-research-protocol/skills/distilling-methods/SKILL.md` as the single detailed rule source (`using-aitp` only points at it): cards are the existing `mode: theory` Note profile (title `Method card: <slug>`, body first line `> method-card: <slug>`, six fixed theory headings; Topic-local, always `review_state: agent_draft`) — no new schema, mode, or review state; draft only on trigger (explicit request, or a stable procedure across ≥ 2 independent sessions/chains, or the same failure plus workaround twice); trial Entries pin the exact card (`sha256:`); revision is a new Note `supersedes` (old cards never edited); **two pinned trials ⇒ publication proposal only**; approval is a human `decision` Entry (`authority: human`) pinning the card; publication into the plugin Skill requires a further explicit human publish request. Since 0.8.0: eligible durable Entries may carry a low-trust `> method-observation: <slug>` marker (candidate, not proof — the runtime never validates it); pre-card Entries are `basis_refs` only, never trials; post-card trials must exact-`sha256:` pin the saved card at creation; two qualifying trials trigger a two-step human decision (card `Approve`/`Defer`/`Reject`, then separate `Publish now`/`Keep local`), both saved as independent human `decision` Entries by the main agent; the platform tool/card/Skill three-layer boundary and the best-effort fallback (no runtime hook, no exactly-once) are defined in the Skill. Never auto-publish, never cross-Topic propagate, never infer `workstreams`, never resolve a failure on a card's authority, never Python-summarize, never let a subagent ask/answer approval/publication questions, never hardcode a model/preset; distillation preserves provenance and requires explicit human approval before publication.
- The 2026-08-15 Harness adjudication boundary (recorded in `docs/method-cards-and-distillation.md`): adopt the card/Skill/tool three-layer separation (card informs, Skill routes, tool executes), fixed card shape, completeness tests, stop-on-mismatch with verification anchors, and human ratification; reject enumerated dispatchers/registries/INDEX, Ion/symlink tooling, bulk card zoos, duplicated facts, prose-only provenance, and tests-not-in-CI. Never claim behavior superiority over plain files.
- Do not add a required vector service, MCP server, hook, or background daemon.
- Keep physical reasoning, synthesis, literature judgment, and collaboration policy in Skills and reviewed artifacts; Python is for deterministic I/O, validation, projection, and benchmarks.
- Agent behavior conformance would be measured by the external suite described in `docs/roadmap.md` (currently **dormant**: FROZEN v6 has never been scored); the runtime never tries to enforce research behavior.
- AITP stores only the external evaluation-harness contract (`docs/external-evaluation-harness.md`); no harness implementation, runtime, or dependency belongs in this repository.
- Documentation must stay inside the trust model: auditable and tamper-evident, never tamper-proof.
- Legacy stores (v5 registries, PROJECT_MEMORY-style memory files, session archives) are preservation evidence; bootstrap them lazily per the M0.6 plan instead of migrating their contents.
- Run the unchanged ledger tests plus stage-specific tests before committing.
