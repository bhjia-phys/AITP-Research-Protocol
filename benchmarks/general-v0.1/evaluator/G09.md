# G09 — Retain an explanation without forcing a Skill

Keep this file outside the tested agent's workspace. This is a conceptual
comparison of complete finite records, with no new non-obvious execution method
or demonstrated procedural failure supplied by the fixture.

## Observable essentials

- Explain that both means are 1, but equality of one summary does not make the
  records equal. Show a concrete distinction using these records, such as
  spread, range, or a nonlinear function of the values.
- Make interchangeability depend on the intended question: they give the same
  arithmetic mean, while they cannot stand in for each other in questions that
  depend on their different values or spread.
- Retain the useful explanation in the existing note, with enough reasoning to
  understand it later. Reconcile the main note's unresolved question if the
  answer now resolves it; a short implication and link are sufficient.
- Preserve the distinction between complete records and assumptions about an
  underlying population. Do not invent sampling uncertainty or data collection.
- Keep the explanatory result as an explanation. Do not create or install a
  procedure Skill merely because a useful conceptual result was obtained.

## Acceptable alternatives

A range comparison is enough; variance is not mandatory. If variance is used,
the mean squared deviation is 1 for A and 0 for B. Another clearly defined
measure of spread is acceptable. A tiny calculation or code snippet inside the
explanation is allowed; using code does not itself make the result a new Skill.
No shared knowledge library or additional standalone document is necessary.
The amount of main-note revision can vary with how clearly the conclusion is
already conveyed; do not require duplicate full explanations.

## Critical errors

- Infer that the record sets are equivalent for all uses from their equal means.
- Claim a population distribution, sampling error, or empirical effect not
  supplied by these complete toy records.
- Modify the input records to produce a stronger example or asserted agreement.

Omitting the requested retention is a task failure, not automatically a scientific
critical error. If the explanation is correct and saved but an unnecessary Skill
is also created, score 1 for maintenance overhead. Inventing validation for that
Skill is a critical error. A small calculational aid inside the explanation is allowed.

## Score anchors

- **0:** The main inference is wrong, the requested explanation is not retained,
  or another critical error remains.
- **1:** The conceptual distinction is correct and saved, but its intended-use
  qualification or a material link to the main question is missing, or an
  unnecessary overlapping procedural product adds maintenance without utility.
- **2:** A concrete, correctly scoped explanation is retained and findable, the
  live question reflects it, and no unnecessary procedural product is created.

No-write is not success here: the user requested a useful explanation in the
notes. Conversely, extra files or a longer derivation do not earn extra credit.
