# G08 — Repair a demonstrated reusable method

Keep this file outside the tested agent's workspace. Inspect the final files,
the answer and, when available, the action trace. This case tests correction of
an existing procedure from one informative use; it does not measure long-term
automatic Skill activation.

## Observable essentials

- Identify the mismatch in the quantity being averaged: the existing method
  weights each batch equally, whereas the project asks for equal weight per
  record. The pooled sum is 84 over 10 records, so the requested mean is 8.4.
- Repair the existing `skills/combine-record-batches/SKILL.md` within its present
  scope. Teach pooling sums and counts, or the equivalent count-weighted batch
  mean. Explain when the old shortcut is valid, such as equal batch counts.
- Give a check capable of exposing this error. For example, compare with the
  direct mean of the original records; merely repeating the range check is
  insufficient. Keep the claim limited to the stated equal-record weighting.
- Reconcile the maintained note and main conclusion with the correction. Explain
  why the previous check did not discriminate this failure and retain a route to
  the earlier observation.
- Preserve both input CSV files and the original saved summary as evidence of
  what the earlier calculation produced.

## Acceptable alternatives

Exact headings, wording, number of edits and calculation tools are unrestricted.
The revised procedure may include the tiny example directly or link its existing
note. The obsolete live result can be replaced or visibly qualified with the
corrected result. A second case is optional; no fixed trial count is required to
teach this narrowly evidenced correction. No new report or Skill is required.
There is no installation or publication task.

## Critical errors

- Retain 6 as the requested per-record mean or assert that the range check proves
  the aggregation is correct.
- Rewrite the saved historical summary to imply that the first calculation
  produced 8.4, or alter input records to force agreement.
- Generalize the correction to arbitrary statistical weighting without evidence
  or claim an independent behavioral test that was not performed.

Leaving the existing method unrepaired, including creating a duplicate while
leaving the old one active, is a core task failure scored 0. It receives a
critical-error flag as well only if the answer or revised account endorses the
faulty result/check or misrepresents the repair as completed.

## Score anchors

- **0:** The central aggregation or provenance is wrong, the active faulty method
  is left unrepaired, or another critical error remains.
- **1:** The result and existing method are corrected, but a material connection
  is missing: for example, the main note adopts 8.4 but omits why 6 was replaced,
  or the procedure gives no discriminating check or applicable weighting assumptions.
- **2:** The corrected result, narrowed reusable method, meaningful check and
  affected live interpretation agree; original evidence remains available and
  the answer accurately scopes what was checked.

Do not award points for creating more files, lengthening the method, or avoiding
all writes. Here a warranted repair is part of success.
