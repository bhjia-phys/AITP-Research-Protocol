# AITP 通用研究工作 benchmark v0.1

这是一个小型、静态的开发与回归题集：12 个普通研究请求，各带可复制的
合成材料和分开的评分依据。它检查读取记忆、维护论证、选择下一步、学习
方法和管理证据的实际行为。它不要求任何私人课题知识，也不衡量前沿物理
发现能力。这里没有运行器、后台服务或新研究记录协议。

当前状态：十二题均已在独立 Codex CLI 会话中完成一次开发回归，按公开的
逐题评分规则均为 2/2；G04 另有一次使用实际产物的只读跨会话续接。
较早的 G07、G08、G12 定向试跑属于不同宿主条件下的预备检查，不能与
正式回归混作同一组结果。尚无普通笔记、旧版 AITP 或优化前后的匹配
对照，因此这些分数不能证明因果改进或普遍可靠性。实际运行材料留在
发布树之外，范围及中断记录见[验证说明](../../docs/validation.md)。
旧版 AITP 的历史成绩不填入本题集。

## 问题集

下表供研究者选择测试；**不要把表中的测试目的或评分文件提供给被测代理**。
实际问题在各题 `prompt.md`，原始材料在其 `workspace/`。多数问题故意不提
“记忆维护”“蒸馏”或 AITP，观察这些行为是否在实际任务中合适地发生。

| 题号 | 通用问题的类型 | 主要观察 |
| --- | --- | --- |
| [G01](cases/G01/prompt.md) | 目前知道什么、还有什么不确定 | 恢复当前结论和条件；无新理解时不写文件 |
| [G02](cases/G02/prompt.md) | 为什么改变路线、当时为什么作出某个选择 | 找到已记录理由；承认没有记录的原因 |
| [G03](cases/G03/prompt.md) | 新增一组对照，整理到合适位置 | 保存支持细节，保持主结论的适用范围 |
| [G04](cases/G04/prompt.md) | 前提更新了，检查已有推导及笔记 | 修正受影响解释，保留有效子结果和历史证据 |
| [G05](cases/G05/prompt.md) | 让开头讲清问题和实际贡献 | 综合结果之间的关系，区分来源与成立条件 |
| [G06](cases/G06/prompt.md) | 继续推进当前研究问题 | 在物理/模型对应缺失时识别无效的精度扩展 |
| [G07](cases/G07/prompt.md) | 继续推进当前研究问题 | 在误差确实阻碍判别时完成已授权的计算 |
| [G08](cases/G08/prompt.md) | 处理这次方法使用中发现的问题 | 从实际证据修正已有方法，避免重复创建 |
| [G09](cases/G09/prompt.md) | 把这次理解整理进已有材料 | 保存概念解释，不强行生成方法 Skill |
| [G10](cases/G10/prompt.md) | 整理并使用已有计算结果 | 区分当前源码与历史执行，复用位置并保留基线 |
| [G11](cases/G11/prompt.md) | 看看计算进展，现在得到什么 | 识别首次重要但临时的结果并整合其意义 |
| [G12](cases/G12/prompt.md) | 只读核查这次结果 | 不改文件，同时明确主文档中待整合的判断 |

G06/G07 是路线判断的配对题，G11/G12 使用相同初始材料和不同编辑范围。
G03/G04 对照支持性新增与前提修正；G08/G09 对照程序学习与概念理解。
它们不是要求统一输出格式的问答题。不同的合理组织方式可以得同样分数。

## 给被测代理什么

每题在新的会话中运行。只提供：该题 `workspace/` 的全新副本、下面的共同
任务说明、该题 `prompt.md` 原文，以及本次条件允许使用的工具和 Skills。
不要让被测代理在这个仓库根目录工作；这里含评分说明、反馈与题目答案。

共同任务说明：

> 这是一个独立的合成研究工作区。请完成随后给出的研究者请求。可以按任务
> 需要读取、计算和修改此工作区内的材料，具体请求中的限制优先。所需数据
> 都在工作区；不访问其他课题、历史会话、外部网络或真实计算集群。只执行
> 与请求相关的本地工作。没有提供的事实应保持未知。

这里的权限只界定可用资源，不告知应修改哪些文件。每题的 `README.md`
是项目材料入口；源码、脚本与运行输出如有提供，都是小型教学用合成材料。
代理知道数据是合成的，不必伪装成真实实验。

把题目副本放在独立临时目录，保持初始副本供评分者比较。通用常识和本地
标准库计算足以完成任务。无需安装依赖、联网、提交 Git 或生成论文 PDF。
任一题都不要求访问另一个题目。

## 分开测三种条件

1. **普通笔记基线**：相同模型、材料、请求、工具和权限，无 AITP 指令。
2. **当前 AITP**：同样条件，提供明确记录的当前 Skill 快照。
3. **优化后 AITP**：仍用同样条件，只改变被比较的 AITP 指令快照。

先确定每次运行的模型、推理设置、工具、时间/令牌预算、重复次数和是否显式
调用 AITP，再保持一致。显式调用比较指令的使用效果；自然发现比较激活和
使用的组合效果。两者分别报告。普通笔记基线也保留同样的完整笔记和证据。
该基线还须排除 AITP 的 Skill 描述、宿主入口提醒、父目录指令和已注入记忆，
仅要求代理“不读取 SKILL.md”不足以实现无 AITP 对照。

提供给代理的 Skill 快照不得包含本题集、评分依据、实际运行观察或私人
研究。记录实际加载的文件，而不只记录仓库 HEAD；工作树有修改时保存所测
文件副本及差异。不能把源码版本、安装缓存和会话实际加载内容视为同一件事。

尽量禁用与题目无关的宿主记忆和历史会话注入，并确认没有评分材料泄漏。
如果宿主不能隔离，就如实记录；这类试跑可以检查题目可用性，不能充当
严格的无 AITP 对照。继承过出题讨论或评分依据的代理不能作为该题独立考生。

每次从相同原始材料开始，不把前一次生成的文件带入另一个条件。唯一例外
是下方明确指定的跨会话续接。超时、失败和请求人工协助的运行也保留，不仅
挑选成功样本。题库修订后改变版本，并重新建立可比基线。

## 评分与预期效果

[评分原则](evaluator/README.md)和 `evaluator/G*.md` 只给评分者。检查最终
回答、实际文件、前后差异与可取得的操作轨迹；不因代理声称“已更新”而得分。
保留逐题 0/1/2、严重错误与证据位置，不用一个平均分盖过错误。

可以用[简短结果模板](evaluator/report-template.md)，把实际输出和完整观察
放在本题集及发布目录之外。未运行写 `未运行`，不能写 0 分或沿用历史成绩。
运行发生但关键证据不够时写 `待评／证据不足`，不要猜测一个分数。
工具调用、阅读与维护成本另报；篇幅更短、文件更多或 Skill 被调用都不是
科学行为更好的充分依据。

## 一个便宜的跨会话检查

执行 G04 后，把该考生实际留下的工作区交给第二个新会话，不修补文件，也不
提供第一会话聊天、新的正确答案或评分材料。第二会话只收到：

> 接着这份材料，我们现在可以用哪个结果，原先的结论为什么需要改变？
> 先给我说明，不用修改文件。

第二会话保留相同模型、AITP 条件和共同资源限制；这里的“不继承”针对聊天
和额外答案，不是撤掉原来的测试条件。

分别记录第一会话的更新质量和第二会话的恢复质量。第二会话应能从文件恢复
完整方程的相容性问题、有效投影结果及改变解释的原因。若第一会话遗漏了
证据，第二会话应说明缺失，不能为了连贯编造。最终没有恢复正确科学含义
仍是链条失败，但应区分写入遗漏与读取误用；不要求后者猜到未保存的内容。
这一检查不增加新的记忆格式。

## 后续用于实际优化

这是一套公开的开发回归题。优化者已经能够看到题目和预期，优化后的高分
只能说明这些案例上的改进，不能声称通过了未见题或证明一般科研优势。

先保留当前版本逐题表现，再围绕失败原因修改 Skills；复测时同时运行对应
正例和负例，避免“永远写主文档”“永远停止计算”等策略得到虚假提升。
之后另选未用于改指令的新实例：改变材料布局、符号、数值和表面问法，并
保持所测的科学区别。由没有读过预期的会话执行。

真实课题测试属于下一层：保持同样的问题类别和评分关注点，把公开合成
材料替换为获准使用的真实材料，另行确定科学正确性的依据、任务范围和资源。
这些私人材料及其运行记录留在发布树之外。通用题集不代替领域准确性测试。
