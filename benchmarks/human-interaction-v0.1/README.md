# Human interaction and branch organization

Four small generic tasks exercise consequential questions, authorized organization,
complete teaching delivery and a learner's valid objection. They are authored
development cases, not a general research-capability benchmark or evidence that
a human learned from an explanation.

Use a fresh disposable workspace and independent session for each case. Load the
AITP version being tested, supply only the selected task from [prompts.md](prompts.md)
and its input files, and keep [evaluator.md](evaluator.md) outside that session.
Preserve the exact answer and resulting files separately from the inputs. When
comparing versions, use the same task and inputs. Do not edit a failed output
before scoring it. The prompts do not require a scheduler, network or new runtime.

For a task needing human input, the first response is the test boundary; record
the question without inventing a reply. This tests how the question is posed,
not the entire subsequent conversation. An explicit Skill load does not test
implicit host activation. Public fixtures contain no private research or results.

See [validation](../../docs/validation.md) for the executed checks and their limits.
