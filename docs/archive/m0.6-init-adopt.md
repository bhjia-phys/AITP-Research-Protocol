# M0.6 gate item 1 — `aitp init --adopt` implementation spec

Status: deterministic implementation complete; local tests pass. Under the
approved narrowed M0.6 closure, this document records implementation evidence
only: the original real-tree operator hash acceptance is not complete and is
not counted as bootstrap validation. Scope: this document is the complete spec
for gate item 1 of `docs/roadmap.md` §M0.6. Nothing beyond this document is in
scope.

## Goal

`aitp init` today refuses any non-blank directory (`workspace_not_blank`).
Real research trees are never blank. `--adopt` creates the `.aitp/` store
inside an existing research tree without touching any existing file and
without imposing the fixed layout (`theory/`, `software/`, …).

## CLI

```
aitp init --adopt --topic <slug> --title "<title>" [--cwd PATH] [--dry-run] [--json]
```

One new flag on the existing `init` subcommand: `--adopt`
(`action="store_true"`). All other flags unchanged. `--dry-run` and `--json`
compose with `--adopt` exactly as they do with plain `init`.

## Behavior

Adopt creates exactly this `.aitp/` subtree and nothing else:

| Path | Content |
|---|---|
| `.aitp/.gitignore` | `local/\n` |
| `.aitp/STORE.toml` | same rendering as `init` (schema `aitp/lite-store-0.1`) |
| `.aitp/topic/TOPIC.md` | template `init/topic.md`, `{goal}` = "Not established yet" |
| `.aitp/local/config.toml` | `workspace_root = <quoted root>` |
| `.aitp/topic/entries/` | empty directory |
| `.aitp/topic/notes/` | empty directory |
| `.aitp/local/drafts/` | empty directory |
| `.aitp/local/scratch/` | empty directory |
| `.aitp/local/locks/` | empty directory |

Adopt must NOT create: root `README.md`, root `.gitignore`, `theory/`,
`software/`, `calculations/`, `data/`, `figures/`, `references/`,
`manuscripts/`, or any other file outside `.aitp/`.

Root resolution, safety, and validation are identical to `init`
(`workspace.py`):

- `resolve_root(cwd)` — walks up to an existing store, else git root, else
  `cwd`. Documented consequence: running `--adopt` in a subdirectory of a git
  repository adopts the git root, not the subdirectory. This matches `init`
  and is intentional.
- `_ensure_safe_root(root)`, `_safe_slug(topic_id, "topic ID")`, non-empty
  title.
- Refuse with `already_initialized` if `root/.aitp` exists (any content —
  adopt never merges into a partial store).
- The `workspace_not_blank` check is the ONLY `init` guard that adopt skips.

Return payload: same keys as `init` plus `"mode"`, i.e.
`{status, root, topic_id, created_files, mode: "adopt"}`. Plain `init` gains
`mode: "init"`. `created_files` lists the four files above (directories are
not listed, matching current `init` behavior).

## Implementation (workspace.py, ~+35 lines)

Split `_init_files` so the store-only part is reusable. Do not restructure
anything else.

1. New private helper `_store_files(root, topic_id, title) -> dict[Path, str]`:
   move the four `.aitp/` entries out of `_init_files` (`.aitp/.gitignore`,
   `STORE.toml`, `topic/TOPIC.md`, `local/config.toml`). Rendering logic is
   copied verbatim — no changes to content, ordering, or templates.
2. `_init_files` becomes: `_store_files(...)` merged with the layout files it
   keeps (root README, root `.gitignore`, folder READMEs, `INDEX.md`,
   `CONVENTIONS.md`, `library.bib`). Output of plain `init` must stay
   byte-identical — the golden fixtures and existing tests prove this.
3. New public function:

   ```python
   def adopt_workspace(
       cwd: str | Path,
       topic_id: str,
       title: str,
       *,
       dry_run: bool = False,
   ) -> dict[str, Any]:
   ```

   Same flow as `init_workspace` minus the blank check: resolve root → safe
   root → slug → title → refuse if `.aitp` exists → `_store_files` → create
   the five store directories (`topic/entries`, `topic/notes`,
   `local/drafts`, `local/scratch`, `local/locks`) → conflict-refusing
   `atomic_write` per file → identical rollback block (delete created files in
   reverse, then created dirs deepest-first) → return payload with
   `mode: "adopt"`.

   Factor the shared create-with-rollback loop into a private
   `_write_files(rendered, directories, dry_run)` used by both
   `init_workspace` and `adopt_workspace` only if the factoring is mechanical;
   duplicating the ~15-line loop is acceptable and preferred over a clever
   abstraction.

4. `core.py` facade: add `adopt_workspace` to the imports and `__all__`.
5. `cli.py`: add `--adopt` to the `init` subparser; in `main`, route
   `args.adopt` to `adopt_workspace(...)`.

Estimated runtime cost: workspace.py +~35, core.py +2, cli.py +~8 → ~+45
nonblank lines, against the M0.6 budget of +119 (981 → 1,100 cap).

## Tests (new file `tests/ledger/test_adopt.py`)

Reuse the fixture style of `test_cli.py` (tmp_path trees, direct `main()`
calls or core calls — match the existing file's convention).

1. **adopt_populated_tree_untouched** — build a tree with nested dirs, files
   at several depths, a `.git/HEAD` marker. Hash every file outside `.aitp`
   (path → sha256) before and after adopt; assert identical mapping.
2. **adopt_creates_exact_store** — assert the nine expected paths exist and
   assert root `README.md`, `.gitignore`, `theory/` etc. do NOT exist.
3. **adopt_refuses_existing_store** — adopt twice; second call raises
   `already_initialized` (or CLI exit 2 with that code).
4. **adopt_dry_run_writes_nothing** — `--dry-run`; assert zero `.aitp` paths
   created and payload `status == "dry_run"`.
5. **adopt_rollback_on_conflict** — monkeypatch `atomic_write` to raise after
   the first file; assert no `.aitp` files or directories remain.
6. **adopt_then_enter** — adopt, then `enter_workspace`; assert
   `memory_status` reports an available empty store (reuse the golden
   fixture's field names; do not invent new ones).
7. **init_output_unchanged** — existing golden and ledger tests already cover
   this; run them, add nothing.

The deterministic local tests establish non-destructive behavior. The heavy
legacy-tree recovery record has no independently locatable hash artifact, and
GW_librpa has no preserved before/after record; this document makes no claim of
complete real-tree hash evidence.

## Explicitly out of scope

- No merging into a partial `.aitp/` (refuse instead).
- No detection or import of existing research content (that is item 2,
  bootstrap).
- No `topics.toml` (plain-file convention, frozen before M1a, no CLI).
- No changes to `enter`, records, notes, or templates.
