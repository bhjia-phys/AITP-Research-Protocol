Status: **closed/done under the approved narrowed reviewed claim**

The 2026-08-10 decision block below is the applied human approval. It closes
M0.6 only under the narrowed reviewed claim; it does not claim bootstrap
validation or AITP advantage over plain files, and it does not alter the CLI,
runtime, tests, suite inputs, or FROZEN v6 bytes. A post-review amendment now
records M1a as **done; deterministic gate passed**; the implementation evidence
is in [`docs/m1a-stage-notes.md`](m1a-stage-notes.md). The historical decision
block remains unchanged.

## Decision boundary

The original full empirical gate was not completed. Bootstrap Notes and human
decision Entries, recall, false-import rate, human time, held-out S3, paired
S1/S2 scores, cold-start metrics, conformance, treatment-over-control
advantage, and causal evidence are **not measured; deferred; not counted**.
FROZEN v6 remains an anchored, unexecuted preregistration. The approved
closure records deterministic implementation evidence and these explicit gaps;
it does not retroactively convert any gap into a result or make a claim that
AITP is better than plain files.

## Approved narrowed claim

> M0.6 establishes non-destructive adoption into existing trees,
> deterministic traversal/order/content hashing in a timestamped local manifest
> whose `generated_at` and absolute `root` make repeated bytes non-identical,
> and an anchored evaluation packet whose no-turn preflight failed closed when
> run prerequisites were unavailable. It does not establish bootstrap recall,
> false-import performance, researcher cost, agent conformance, or
> treatment-over-control advantage.

Under this claim, the allowed conclusions are limited to:

- the canonical `init --adopt` and `inventory` implementation exists and is
  covered by deterministic local tests; `inventory` provides deterministic
  traversal/order/content hashing in a timestamped local manifest whose
  `generated_at` and absolute `root` make repeated manifest bytes
  non-identical;
- the local runtime remains within the M0.6 budget and the unchanged ledger
  suite is green;
- a recorded heavy-legacy-tree byte-identity check exists according to the
  recovery evidence, while the GW_librpa adoption has a separate, explicit
  evidence gap documented below;
- FROZEN v6 is an anchored, unexecuted preregistration, and its preflight
  correctly failed closed rather than consuming an invalid held-out run; and
- no claim is made that AITP improves research behavior, reduces researcher
  cost, improves recall or precision, or beats the plain-files control.

## Completed deterministic evidence

### Adoption and inventory implementation

- `tests/ledger/test_adopt.py::test_adopt_populated_tree_untouched` hashes a
  populated temporary tree before and after adoption, excluding only the new
  `.aitp/` store, and requires identical file-byte maps. The same test module
  covers exact store creation, refusal of an existing store, dry-run, rollback,
  and `enter` after adoption. This is deterministic fixture evidence, not a
  substitute for the missing GW_librpa operator hash record.
- `tests/ledger/test_inventory.py` exercises traversal/exclusion behavior,
  symlinks without hashes, content SHA-256 and byte counts, replacement of a
  same-name manifest, missing-store refusal, and comparison with `sha256sum`.
  The implementation deterministically traverses/orders paths and hashes
  content in a timestamped local manifest; its `generated_at` and absolute
  `root` make repeated manifest bytes non-identical.
- The implementation is confined to the canonical runtime at
  `plugins/aitp-research-protocol/scripts/vendor/aitp/`. No runtime, suite,
  test, manifest, or frozen input was changed for this Phase 1 packet.

### Frozen evaluation packet and failed-closed preflight

- `suite/FROZEN.md` records v6 as the operative freeze and names immutable
  anchor commit `145261805d5205d2150dca18c6c42d5a18a628f2`.
- The archived operator preflight is documented at
  `suite/runs/2026-08-09-preflight/S3/` in
  [`docs/m0.6-stage-notes.md`](m0.6-stage-notes.md). It verified the 15 frozen
  input hashes, the S3 seed manifest
  `697326340cd3a5042241c3cde1308fd4a2ed294d33316606a2b26e7ae6890530`, a
  clean suite path, the treatment export, and packet neutralization. It sent
  no participant turn and produced no score.
- The preflight stopped before the execution-order draw and first prompt
  because exact model/provider and prompt bytes, agent configuration, and
  genuinely separate treatment/control machines or accounts were unavailable.
  Same-account namespace separation was correctly not accepted as a
  substitute.
- The preflight is therefore auditable preparation and an invalid-start
  decision, not a held-out S3 report and not paired scored evidence.

## Real-tree hash-evidence gap

The two real-tree adoption statements must not be merged:

- **Heavy legacy tree:** the recovery evidence states that byte-identical
  before/after evidence was recorded. An exact repository or Git-history
  locator containing the before/after manifests, tree hashes, or the named
  tree is **unavailable**. This packet preserves the historical distinction
  without inventing a path, commit, or digest.
- **GW_librpa:** adoption succeeded, but the original session preserved no
  before/after tree-hash record. An exact repository or Git-history locator for
  such a record is **unavailable**. The repository's read-only acceptance text
  and the adopt unit tests specify or exercise the behavior; they do not create
  a retrospective real-tree hash record.

Consequently, this review makes no claim that both dogfood trees have
preserved before/after hashes. The GW_librpa read-path acceptance remains
future evidence, and the heavy-tree record is not independently locatable in
this repository.

## `topics.toml` status

`topics.toml` is not present as a repository file and is not a runtime command.
The M0.6 contract is a plain-file convention documented in
[`docs/roadmap.md` §M0.6](roadmap.md) and
[`docs/cross-topic-links.md` §Layout](cross-topic-links.md#layout): portable
Topic IDs and metadata belong in `topics.toml`; local absolute-path mapping is
separate and machine-local. Humans and agents can read the file directly.

There is no catalog CLI in M0.6, and the M3 catalog/link design remains blocked
until natural cross-Topic use demonstrates a need beyond `rg` and ordinary
citations. The absence of a `topics.toml` file in this repository is therefore
not a failed runtime test and is not counted as M0.6 gate evidence.
