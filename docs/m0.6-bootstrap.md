# M0.6 gate item 2 — legacy bootstrap spec

Status: ready for implementation. Scope: gate item 2 of `docs/roadmap.md`
§M0.6. Bootstrap is deliberately lazy and shallow: inventory + manifest +
one orientation Note per active Topic, confirmed by a human decision Entry.
It is not a migration.

## What bootstrap must and must not do

Must: give a returning agent enough orientation to resume an active Topic
whose history lives in a pre-AITP (legacy) tree, with every imported claim
traceable to an exact legacy locator.

Must not: revalidate legacy science, rewrite legacy files, import legacy
decisions/failures/conventions as verified records, or block on completing
bootstrap for inactive Topics (they bootstrap on first re-entry, same
procedure).

## Component 1 — `aitp inventory` (runtime, ~+50 nonblank lines)

```
aitp inventory <path> --name <slug> [--cwd PATH] [--json]
```

Read-only recursive scan of `<path>`; writes one manifest into the store
resolved from `--cwd` (default `.`). Requires an existing store (run after
`init` or `init --adopt`).

Rules:

- Skip `.git/` directories at any depth; skip the store's own `.aitp/` if it
  lies under `<path>`. Follow no symlinks; record them as
  `{path, type: "symlink"}` entries without hashing.
- Hash every regular file with sha256; record size in bytes.
- Sort entries by path; atomic-write
  `.aitp/local/legacy/<slug>-inventory.json`:

  ```json
  {
    "schema": "aitp/legacy-inventory-0.1",
    "name": "<slug>",
    "generated_at": "<UTC ISO>",
    "root": "<absolute scanned path>",
    "files": [{"path": "<relative>", "sha256": "<hex>", "bytes": 123}]
  }
  ```

- `--name` passes `_safe_slug`; existing manifest of the same name is
  overwritten atomically (re-inventory is expected as legacy trees change).
- The manifest lives under `.aitp/local/` — it is a local index, not a
  canonical record. Payload: `{status, name, manifest, files, bytes}`, where
  `manifest` is the store-relative manifest path, `files` counts hashed
  regular files (symlink entries excluded), and `bytes` sums their sizes.

Implementation: add `build_inventory()` to `workspace.py` (hashing + walk,
~35 lines) plus CLI wiring (~10 lines). The store lookup uses the existing
`load_store(resolve_root(cwd))`. Budget check: 981 + ~45 (adopt) + ~50
(inventory) ≈ 1,076 ≤ 1,100 cap. Both commands must land minimal; no
options beyond this spec.

## Component 2 — records (existing commands, no new runtime)

Per legacy corpus (one or more per Topic):

1. A `source` Entry whose refs pin the manifest by `sha256:` and pin each
   load-bearing legacy file it cites. `limitations` section states the
   corpus was not re-validated. Body names the corpus, its role, and its
   date range.
2. One bootstrap **working Note** per active Topic (`note prepare --mode
   working` / `note save`), written by the agent after reading the inventory
   and the load-bearing files. Required body conventions:
   - first line: `> legacy-derived: recovery orientation only — not
     re-validated`;
   - every imported fact carries an exact legacy locator
     (`path:line`/`path#section`) and, where the fact is quantitative, the
     file's sha256 from the manifest;
   - an explicit `Unknown / not yet located` section listing what the agent
     looked for and failed to find;
   - ends with `Next actions` for the returning session.
3. A `decision` Entry, `authority: human`, refs pinning the saved Note file
   by sha256, whose body records in substance: "The researcher confirms this
   Note as recovery orientation only. It is not re-validated science.
   Corrections supersede it through normal records."

Legacy decisions, failures, and conventions enter only as individually
confirmed drafts marked legacy-derived in the body — never as new
verification, never in bulk.

## Component 3 — measurement protocol (no code)

Before bootstrap starts on a dogfood Topic, the researcher writes
`.aitp/local/legacy/<topic>-goldset.md`:

- **Key facts** (≥ 10): atomic facts a collaborator must be able to recall
  after bootstrap (conventions, notation, decisive past results, dead ends).
- **Traps** (≥ 3): plausible but wrong/stale claims the bootstrap must NOT
  import (superseded conventions, abandoned wrong turns).

Metrics, computed per Topic after the human confirmation step:

- **Key-fact recall**: fraction of gold-set key facts present and correctly
  located in the bootstrap Note (human-judged against the gold set).
- **False-import rate**: denominator = judgeable atomic claims in the
  bootstrap Note (enumerated during review); numerator = claims that are
  false, stale, or unsupported by their cited locator. Traps imported count
  here.
- **Human time**: wall minutes from the researcher starting the gold set to
  signing the decision Entry, with start/stop noted in the stage notes;
  reported as the median across dogfood Topics.

## Gate item 2 acceptance

On both dogfood Topics:

- [ ] manifest written at the fixed path, valid JSON, hashes spot-checked
      against `sha256sum`;
- [ ] bootstrap Note carries the orientation marker, locators, and the
      `Unknown / not yet located` section;
- [ ] human `decision` Entry pins the Note's sha256;
- [ ] key-fact recall and false-import rate computed against the pre-written
      gold set and recorded in the stage notes with the human-time median;
- [ ] full test suite green; runtime ≤ 1,100 nonblank lines cumulative.

## Explicitly out of scope

- No installed Skill for bootstrap (the procedure above is the spec; a Skill
  may be distilled later from real runs, per the distillation rules).
- No parsing of legacy file formats, no automatic claim extraction.
- No bulk import of legacy history into Entries.
- No re-inventory automation or watching; re-run `aitp inventory` by hand.
